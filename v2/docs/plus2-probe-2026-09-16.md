|---|---:|

## 2. Candidate (a) — the FO profile

`cpuBoardValue` reads `frontOffice(state, teamId)` for `risk` and
`bpaBias`. The 2026-09-14 write-up called the user's FO "neutral".
**That is a slight misread of generate.** `createNewGame` already
runs `assignFrontOffices` across all 32 clubs, user included.
`frontOffice()` for the user is a shuffled+jittered archetype, not
`DEFAULT_FRONT_OFFICE` (Balanced, risk 0.50, bpaBias 0.55).

What *is* systematically even is **staff**: `refreshCpuStaff` skips
the user, so scouting share stays q = 1.000. The audit already
measured that and ruled scouting out.

The `fo` arm therefore does the experiment as specified: after
`newGame`, replace the user's FO with `makeFrontOffice` from a
random `ARCHETYPES` draw, on a child stream keyed `(seed, "plus2-fo")`
so the parent RNG does not move. Staff stays even. Same housekeeping
as `control`. If the +2 vanishes, the cause was this user's FO
dials (or the particular generate draw). If it persists on both
`control` and `fo`, FO is not the cause — control was already a
random FO.

The JSON emits `userFrontOffice.before` / `.after` and
`scoutQuality` so a reader can see the draw.

## 3. Candidate (b) — clock-trade winner's curse

`tryCpuClockTrade` is the only CPU→CPU on-the-clock path. The buyer
is the club whose private board has a tier break; the user is never
a buyer (`seen` includes `userTeamId`). If that optimistic read is
wrong more often than not, move-up picks are worse than the slot,
the CPU neighbourhood mean drops, and the user's original-owner
picks look +2 against it.

**Tag.** After a successful `executeTrade` + `syncPicksToOwners`,
the on-clock `DraftPick` is stamped `acquiredByClockTrade: true`.
Optional; older saves load. Not written by pre-draft trades,
`acceptClockOffer`, or `acceptMoveUp`. Not read by any decision.

**Groups**, snapshotted after `runFullDraft` / `userDraft` (draft
is still live; `enrol` runs after rollover would null it):

| group | definition |
|---|---|
| `clock` | `acquiredByClockTrade` |
| `original` | `teamId === originalTeamId` and not clock |
| `other` | offseason / draft-day trade, not clock |

**Number.** `plus2.clockVsOriginal` = slot value of clock CPU picks
against the original-owner CPU neighbourhood (±8, min 5 peers).
Negative ⇒ move-ups pay the winner's curse. `otherVsOriginal` is
reported so pre-draft trades do not hide in the clock cell.

Slot value is draft-time. It does not need the four-year mature
cutoff. A 3-season run still emits it.

## Measurement notes

- Do not scan `state.log` for clock trades (`trimLog`). The stamp
  is on the live `DraftPick`; `d.clockTrades` is the count.
- Snapshot origins in the draft phase, before `enterCampAfterDraft`
  / rollover. `enrol` runs after the offseason loop; `state.draft`
  is null by then.
- `enterDraft` already runs `runDraftUntilUser` (and therefore
  `tryCpuClockTrade`) before the draft-phase `runFullDraft`. The
  stamp is inside `tryCpuClockTrade`, so both halves are tagged.
- User slot-value peers are CPU picks. Clock slot-value peers are
  original-owner CPU picks only — including other clock picks in
  the neighbourhood would shrink a real curse.
