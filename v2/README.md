# Gridiron GM

A pro-football front-office simulation that runs entirely in the browser.

```bash
npm install
npm run dev      # http://localhost:3000
```

No database, no account, no API keys. A save is one JSON document in IndexedDB,
and can be exported to a file from the Saves screen.

## What's in it

- **A real simulation.** Games are played drive by drive. Points only ever come
  from a scoring play that also writes the matching player stats, so the box
  score always reconciles with the final score — including defensive returns,
  kick and punt return scores, two-point conversions and safeties.
- **Everything football tracks.** Quarterbacks scramble and sneak. Fumbles are
  contested, not automatic turnovers. Kick and punt returns, tackles for loss,
  forced fumbles and recoveries, interception return yards, longest gains, time
  of possession, red zone and fourth-down efficiency, first downs split by
  pass/rush/penalty, punts inside the 20.
- **A record book.** All-time single-game records captured as games finish, plus
  season, career and franchise leaderboards derived from stored stat lines.
- **Your depth chart decides who plays.** The engine reads it directly.
- **Every attribute does something.** All 30 probes in `npm run leverage` show a
  measurable, correctly-signed effect — verified by changing one attribute at a
  time and simulating 150 identical games, not by correlation (attributes
  co-vary at generation, so correlation lies).
- **Coverage is assigned before the snap.** A defence either travels its best
  corner with the opponent's number one receiver or plays sides — a coach trait.
  Assignments hold all game, so route running versus coverage is a real
  individual battle, and quarterbacks throw away from it. Put a shutdown corner
  on a number one and he loses ~35 yards a game while the number two gains.
- **Game-day conditions.** Weather is generated per game from the home venue's
  climate and the week of the season. Wind suppresses the deep ball and shortens
  kicking range, cold costs ball security, snow pushes teams to the run. Domes
  are always clear. Home field is worth ~2 points and 55% of games, and it runs
  through mechanisms — crowd noise on visiting-offense penalties, a visiting
  kicker penalty — not one invisible fudge factor. A bye is worth a little.
- **17-game schedule** with 8–9 home games, one bye, no team playing twice in a
  week — generated by constraint search, verified every time.
- **Standings with real tiebreakers** (head to head, division, conference, point
  differential), and a 7-seed bracket that reseeds each round.
- **Contracts with proration and dead money.** Cutting a star costs you.
- **Aging, development and retirement** driven by position-specific age curves.
- **A draft with genuine uncertainty** — the range you see is centred on a
  *wrong* number until you spend scouting points on it.
- **CPU teams** that draft on need and value, bid in free-agency waves, and
  respect the same cap and roster rules you do.

## Verifying it

```bash
npm run verify        # multi-season invariant harness
npm run calibrate     # simulation output vs NFL rates
npm run statcheck     # stat persistence + season-leader realism
npm run tails         # how OFTEN milestone games happen vs NFL history
npm run leverage      # does each attribute actually change outcomes?
npm run conditions    # weather, home field and rest, measured over real seasons
npm run coherence     # do big games have REASONS, or do they happen to nobody?
npx tsx scripts/sweep.ts 40 2    # 40 random leagues, 2 seasons each
node scripts/e2e.mjs             # full season in a real browser
node scripts/e2e-interact.mjs    # release / sign / scout / draft flows
```

`statcheck` proves season totals equal the sum of that player's box scores
field by field, then prints season leaders and single-game highs against real
NFL benchmarks.

## Baseline

These are the numbers the locked engine produces. They are here so a future
change has something to regress against: run `calibrate`, `tails` and
`conditions` after touching `lib/core/sim/game.ts` and compare.

**Per team-game** (1,500 games)

| | sim | NFL | | sim | NFL |
|---|---|---|---|---|---|
| Points | 22.1 | 22.5 | Sacks | 2.35 | 2.4 |
| Plays | 64.1 | 63 | Turnovers | 1.31 | 1.3 |
| Pass yards | 232 | 230 | Fumbles | 1.20 | 1.3 |
| Rush yards | 116 | 115 | Penalties | 6.4 | 6.2 |
| Pass attempts | 34.5 | 34 | Time of poss | 30:12 | 30:00 |
| Completion % | 65.7 | 65 | Red zone TD% | 58.9 | 55 |
| Pass TD | 1.48 | 1.5 | 4th down att | 1.77 | 1.9 |
| Rush TD | 0.91 | 0.9 | FG% | 85.5 | 85 |
| Yards per carry | 4.26 | 4.3 | FG attempts | 1.83 | 1.9 |
| Interceptions | 0.72 | 0.8 | First downs | 19.0 | 20.5 |

Reconciliation is exact: **0 score mismatches** across every game of every
harness. The box score always equals the scoreboard.

**Season leaders** land where real ones do — roughly 4,800 passing yards,
1,800 rushing, 1,700 receiving, 19 sacks, 172 tackles.

**Records** are breakable but not routinely shattered. Over 24 simulated
seasons the best single games were 538 passing / 331 rushing / 280 receiving
yards against real records of 554 / 296 / 336, and the best seasons were 5,426
passing / 2,116 rushing / 1,887 receiving against 5,477 / 2,105 / 1,964.

**Conditions** (24 seasons, 8,700 games): home teams win 55.3% and outscore
visitors by 1.99 points (NFL ~55% and ~2.0). Relative to a dome, cold games
score 2.4 fewer points, 20mph winds 3.4 fewer, and snow 4.2 fewer, with pass
rate falling from 57% to 49% and kicking range shortening by seven yards.

**Attribute leverage**: all 30 probes move their metric in the right
direction, and every attribute weighted into a position's overall rating has a
measurable effect on the field.

**Outlier coherence**: 93.6% of 200-yard receiving, 150-yard rushing and
400-yard passing games have at least two explaining factors — an elite player,
a weak opponent, volume, or weather.

### Known variances

Honest about what is still off, so nobody mistakes these for bugs:

- **Punts run about 3.6 a game against an NFL 4.2**, because drives average
  6.0 plays against an NFL 5.5. Third-down conversion (37%) and punt volume
  pull against each other at this drive length; the balance point chosen keeps
  scoring, yardage and every individual stat line correct.
- **First downs are ~1.5 low** for the same reason.
- **10-interception seasons never happen** (NFL: about one every five years).
  Everything else in the interception distribution is right.
- **Three-sack games are somewhat too common** (32 a season against 22),
  though four, five and six-sack games are all at NFL rates.

## Cap rules

You cannot **sign** past the cap — free agency checks roster space, cap space
and the player's asking price, and refuses with a reason. You *can* go over by
**releasing** someone: dead money can exceed a cap hit, which is the point.
Draft picks aren't cap-checked either, since rookie deals are small.

The hard gate is at kickoff: **the season will not start while you are over the
cap or off 53 players.** The "Needs attention" card on the hub has an Auto-fix
that signs, releases and renegotiates until you're legal.

`verify` asserts the things that actually matter: box scores reconcile with the
final score across every scoring route, rosters stay at 53 with position
minimums, nobody is over the cap at kickoff, playoff seeding is deterministic,
every player ages exactly once a year, time of possession sums to the length of
the game, made never exceeds attempted on any stat, giveaways on one side equal
takeaways on the other, the record book stays sorted and points at real players,
and the whole state round-trips through JSON.

`calibrate` reports ~35 rates against NFL benchmarks, both from synthetic
matchups and from three fully played seasons (the season pass catches things
synthetic matchups hide, like league parity).

`leverage` is the guard against decorative attributes. It clones a league,
changes exactly ONE attribute, and simulates the same matchup 150 times with
paired random seeds. Season-long correlation is useless here — `generateAttrs`
builds every position-relevant attribute around the same target, so awareness
once correlated with quarterback passing yards at r=0.51 while the engine never
read it. Anything weighted into a player's OVR must move its metric.

`conditions` splits real seasons by weather and venue to confirm the effects are
real and correctly signed.

`coherence` asks the question frequency cannot. A sim can produce exactly the
right number of 200-yard receiving games and still be wrong, if the players
having them are random — before coverage assignments existed, a 70-OVR receiver
caught 19 balls from a 66-OVR quarterback for 245 yards. Every outlier is now
checked for a TALENT reason (the player is good, or the opponent is not) plus a
second factor. Volume and game script alone don't count as an explanation.

`tails` is the one that matters most for records. Averages being right does not
mean the extremes are: a sim can hit 22.5 points a game and still produce a
500-yard passer every other week. It simulates 16 seasons and measures how often
47 milestone performances occur against how often they occur in real NFL history
— 400-yard games, 200-yard rushing days, 2,000-yard seasons, 20-sack years — so
records get broken at roughly the rate they should be.

## Layout

```
lib/core/
  types.ts        domain model — one array of players, one serializable state
  rng.ts          seeded PRNG (nothing calls Math.random)
  ratings.ts      position weights; OVR is derived, never stored authoritative
  generate.ts     league, players, coaches, contracts
  schedule.ts     constraint-based schedule generation
  sim/game.ts     the play engine
  season/         standings, playoffs, stats, week engine
  offseason/      progression, contracts, draft, free agency
lib/store/        zustand store + IndexedDB persistence
app/              one route per screen, all reachable from the nav
scripts/          verification harnesses
```
